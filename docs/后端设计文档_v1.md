# 后端设计文档 v1

## 1. 文档目的

本文档描述当前版本计算器系统的 C++ 后端设计方案。

后端主要负责：

1. 接收前端 HTTP 请求；
2. 解析请求数据；
3. 验证数学表达式；
4. 将中缀表达式转换为后缀表达式；
5. 执行数学计算；
6. 处理计算错误；
7. 存储与查询历史记录；
8. 删除指定历史记录；
9. 将结果或错误转换为 HTTP + JSON 响应。

---

## 2. 后端总体模块

第一版后端划分为四个主要模块：

```text
C++ Backend
│
├── API Layer
├── Expression Parser
├── Calculator / Evaluator
└── Database Access Layer
```

当前不单独增加独立“异常处理模块”。

错误采用：

> **各模块就地检测 + 统一错误类型 + API 层统一转换响应**

的方式处理。

---

## 3. API Layer

API 层负责后端与前端之间的网络通信。

其职责包括：

- 接收 HTTP 请求；
- 根据 HTTP Method 与 URL Path 判断请求类型；
- 读取 JSON Request Body；
- 调用相应后端模块；
- 获取处理结果；
- 将结果或错误封装为 JSON；
- 返回合适的 HTTP 状态码。

API 层不负责具体数学运算，也不直接处理数据库逻辑。

---

## 4. API Design v1

### 4.1 计算接口

```http
POST /api/calculate
```

用途：

> 前端提交一个表达式，请求后端计算。

请求：

```json
{
  "expression": "(1+2)*3"
}
```

成功：

```http
200 OK
```

```json
{
  "success": true,
  "result": 9
}
```

用户输入相关错误：

```http
400 Bad Request
```

例如：

```json
{
  "success": false,
  "message": "Invalid expression"
}
```

或：

```json
{
  "success": false,
  "message": "Division by zero"
}
```

内部错误：

```http
500 Internal Server Error
```

```json
{
  "success": false,
  "message": "Internal server error"
}
```

---

### 4.2 查询历史记录

```http
GET /api/history
```

用途：

> 获取数据库中的历史计算记录。

无 Request Body。

成功响应示例：

```json
{
  "success": true,
  "history": [
    {
      "id": 1,
      "expression": "1+2",
      "result": 3,
      "created_at": "..."
    }
  ]
}
```

无历史记录时：

```json
{
  "success": true,
  "history": []
}
```

---

### 4.3 删除历史记录

```http
DELETE /api/history/{id}
```

例如：

```http
DELETE /api/history/17
```

表示：

> 删除 `id = 17` 的历史记录。

成功：

```json
{
  "success": true
}
```

如果记录不存在：

```http
404 Not Found
```

```json
{
  "success": false,
  "message": "History record not found"
}
```

## 5. Expression Parser

Expression Parser 负责将用户输入的字符串转换为可计算的后缀表达式。

总体流程：

```text
原始字符串
      ↓
Tokenizer
      ↓
Token Sequence
      ↓
Syntax Validation
      ↓
Unary / Binary Recognition
      ↓
Infix → Postfix
      ↓
Postfix Token Sequence
```

---

## 6. Tokenizer

Tokenizer 将原始字符串拆分为 Token。

例如：

```text
12.5 + 3 * (4 - 1)
```

转换为：

```text
NUMBER(12.5)
PLUS
NUMBER(3)
MULTIPLY
LEFT_PAREN
NUMBER(4)
MINUS
NUMBER(1)
RIGHT_PAREN
```

第一版支持：

```text
NUMBER
PLUS
MINUS
MULTIPLY
DIVIDE
LEFT_PAREN
RIGHT_PAREN
```

Tokenizer 同时负责发现：

- 非法字符；
- 非法数字格式。

例如：

```text
12.3.4
2 + abc
```

均应在 Tokenizer 阶段发现。

---

## 7. Syntax Validation

Syntax Validation 使用“当前期待什么”的方式检查 Token 顺序是否合法。

维护两种核心状态：

```text
EXPECT_OPERAND
EXPECT_OPERATOR
```

### 7.1 EXPECT_OPERAND

允许：

```text
NUMBER
(
一元 +
一元 -
```

不允许：

```text
*
/
)
```

### 7.2 EXPECT_OPERATOR

允许：

```text
+
-
*
/
)
表达式结束
```

第一版不支持隐式乘法，因此：

```text
1 2
3(4+5)
```

视为非法。

---

## 8. 一元 / 二元运算符识别

`+` 与 `-` 可能是一元，也可能是二元。

如果当前状态为：

```text
EXPECT_OPERAND
```

则 `+/-` 被识别为：

```text
UNARY_PLUS
UNARY_MINUS
```

例如：

```text
-5
3 * -2
(-4)
```

如果当前状态为：

```text
EXPECT_OPERATOR
```

则 `+/-` 被识别为普通二元运算符。

---

## 9. 括号检查

遇到：

```text
(
```

记录未匹配左括号，并保持：

```text
EXPECT_OPERAND
```

遇到：

```text
)
```

要求：

1. 当前已经形成完整操作数；
2. 前面存在未匹配的 `(`。

表达式结束时必须保证全部括号匹配。

例如：

```text
(1+2)      合法
((1+2))    合法
(1+2       非法
1+2)       非法
()         非法
```

---

## 10. 中缀转后缀

Parser 使用 **Shunting-yard Algorithm（调度场算法）** 将中缀表达式转换为后缀表达式。

例如：

```text
1 + 2 * 3
```

转换为：

```text
1 2 3 * +
```

转换过程中维护：

```text
output
operators
```

规则：

```text
NUMBER
→ 直接输出

(
→ 压入 operators

)
→ 弹出运算符到 output，直到遇到 (

普通运算符
→ 根据优先级处理栈顶运算符
→ 当前运算符压栈

输入结束
→ 清空 operators
```

---

## 11. 运算符优先级

第一版优先级：

| 运算符 | 类型 | 优先级 | 操作数数量 |
|---|---|---:|---:|
| `u+` | 一元正号 | 3 | 1 |
| `u-` | 一元负号 | 3 | 1 |
| `*` | 乘法 | 2 | 2 |
| `/` | 除法 | 2 | 2 |
| `+` | 加法 | 1 | 2 |
| `-` | 减法 | 1 | 2 |

例如：

```text
3 * -2
```

可转换为：

```text
3 2 u- *
```

---

## 12. Calculator / Evaluator

Calculator 负责对后缀表达式进行求值。

使用一个数字栈。

例如：

```text
1 2 * 3 +
```

处理：

```text
1 → [1]
2 → [1, 2]

*
→ 1 * 2
→ [2]

3
→ [2, 3]

+
→ 2 + 3
→ [5]
```

最终结果：

```text
5
```

---

## 13. 二元运算规则

遇到：

```text
+ - * /
```

要求数字栈至少有两个操作数。

弹栈顺序：

```text
right = pop()
left  = pop()
```

执行：

```text
left operator right
```

对于减法与除法，操作数顺序必须正确。

---

## 14. 一元运算规则

遇到：

```text
u+
u-
```

要求数字栈至少存在一个操作数。

例如：

```text
2 u-
```

得到：

```text
-2
```

然后重新压入数字栈。

---

## 15. 除零检查

除零属于求值阶段错误。

例如：

```text
10 / (3 - 3)
```

Parser 可正常转换为：

```text
10 3 3 - /
```

Calculator 计算：

```text
3 3 -
→ 0

10 0 /
```

执行除法前检查：

```text
right == 0
```

若成立：

- 停止求值；
- 返回 `Division by zero`；
- 不写入历史数据库。

---

## 16. Calculator 防御性检查

即使 Parser 已进行语法验证，Calculator 仍进行基本检查。

二元运算：

```text
数字栈至少 2 个值
```

一元运算：

```text
数字栈至少 1 个值
```

全部 Token 执行结束：

```text
数字栈必须恰好剩 1 个值
```

否则视为求值异常。

---

## 17. Database Access Layer

数据库采用：

```text
SQLite
```

第一版只设计一张表：

```text
calculation_history
```

结构：

```sql
CREATE TABLE calculation_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    expression TEXT NOT NULL,
    result REAL NOT NULL,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

字段：

| 字段 | 作用 |
|---|---|
| `id` | 历史记录唯一标识 |
| `expression` | 用户原始表达式 |
| `result` | 计算结果 |
| `created_at` | 计算时间 |

数据库层负责：

```text
初始化数据库
插入历史记录
查询历史记录
删除指定 ID 的历史记录
```

建议逻辑接口：

```text
insertHistory()
getHistory()
deleteHistory(id)
```

数据库层不关心 HTTP。

---

## 18. 异常处理设计

当前不新增独立异常处理模块。

采用：

> 各模块就地检测 + 统一错误类型 + API 层统一转换 HTTP 响应

错误设计：

| 错误情况 | 发现位置 | HTTP 状态码 |
|---|---|---:|
| 非法字符 | Tokenizer | `400` |
| 非法数字格式 | Tokenizer | `400` |
| 表达式结构错误 | Syntax Validation | `400` |
| 括号不匹配 | Syntax Validation | `400` |
| 除以 0 | Calculator | `400` |
| 求值异常 | Calculator | `400` 或内部错误 |
| 历史记录不存在 | Database/API | `404` |
| 数据库操作失败 | Database Layer | `500` |
| 未知后端异常 | API 顶层 | `500` |

传递流程：

```text
出错模块
   ↓
统一错误信息
   ↓
API Layer
   ↓
HTTP Status + JSON
   ↓
Frontend
```

## 19. 后端核心流程

### 19.1 计算

```text
POST /api/calculate
        ↓
     API Layer
        ↓
Expression Parser
        ↓
    Calculator
        ↓
   计算成功？
   ↙       ↘
 否          是
 ↓           ↓
返回错误   Database Layer
             ↓
           保存记录
             ↓
           返回结果
```

### 19.2 查询历史

```text
GET /api/history
        ↓
     API Layer
        ↓
Database Access Layer
        ↓
查询数据库
        ↓
返回历史记录
```

### 19.3 删除历史

```text
DELETE /api/history/{id}
        ↓
     API Layer
        ↓
Database Access Layer
        ↓
删除指定记录
        ↓
返回处理结果
```
